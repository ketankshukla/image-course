# Volume 10 Dual-Project Handoff Roadmap

## Goal

Turn Volume 10 into the implementation handoff for two separate full-stack projects. Preserve the diagram-first teaching order, complete explanation, standards-status label, Maya case study, dual-stack map, lab, checkpoint, glossary, and primary-source register from one structured lesson source.

## Recommended first release

1. Freeze the framework-neutral blueprint, shared schemas, fixtures, acceptance cases, threat model, evaluation plan, operations pack, and version manifest.
2. Build the Next.js/React project as a separate artifact that owns the accessible web, visual course, typed product state, human-control interface, and Vercel deployment.
3. Build the Python/FastAPI project as a separate artifact that owns domain rules, orchestration, protocol adapters, policy, durable work, data, audit, and service deployment.
4. Reunite them only through shared wire contracts, synthetic fixtures, conformance cases, correlation, and end-to-end user outcomes.
5. Keep all demonstrations synthetic until the correct authority and environment exist; never ship secrets, real customer records, private prompts, or uncontrolled production telemetry.
6. Present proposed targets as illustrative until later implementation produces valid measured evidence with method, denominator, versions, and limitations.

## Blueprint laboratories

- Use-case boundary lab: compare documentation, workflow, assistant, agent, and automation choices.
- Risk and authority lab: bind proposals to evidence and inject unacceptable outcomes.
- Contract conformance lab: run the same valid, invalid, stale, duplicate, and unknown-version fixtures against TypeScript and Python adapters.
- Deployment topology lab: remove providers, regions, workers, queues, and stores, then observe degraded modes and recovery ownership.
- Storage lab: demonstrate authoritative records, derived vectors, caches, queues, artifacts, deletion, backup, and restore.
- Telemetry lab: follow one synthetic task through traces, evaluations, analytics, cost, privacy filtering, and evidence manifests.
- Release lab: promote an immutable build through contract, security, accessibility, evaluation, migration, canary, rollback, and restore gates.
- Readiness board: issue pass, fail, or expiring exception decisions with named evidence and reviewers.
- Game-day controller: inject bounded failures, exercise runbooks, reconcile state, and publish findings.
- Portfolio evidence explorer: follow every claim from requirement through architecture, contract, test, deployment, and measured or clearly illustrative proof.

## Accessibility definition of done

- Every diagram has meaningful alt text and a complete adjacent explanation.
- Every interactive control is keyboard reachable and exposes state without relying on color, hover, or animation.
- Architecture, authority, risk, gate, failure, recovery, and evidence states always have text labels.
- Simulations provide pause, step, reset, reduced motion, and safe synthetic data.
- Proposed targets, sample scores, and exercise values are labeled as scenarios, never measured project results.
